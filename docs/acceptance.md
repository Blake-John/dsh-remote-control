## 已知不兼容：华为 ArkWeb 内核（2026-10-28）

**现象**：华为平板自带浏览器（`HuaweiBrowser / ArkWeb`，UA 报 Chrome/144）通过入口能正常登录、聊天，但**文件预览一直显示"文件资源服务不可用"**。

**排查过程**（三层诊断：socket 生命周期日志、页面错误回传、页面内主动探测）：

| 检查项 | 结果 |
|---|---|
| 服务端 RPC 直测 `workspaceFiles/*` | ✅ 服务存在、可达 |
| 平板 WebSocket 握手 | ✅ 每次 101（1–2ms），有存活 984s 的长连接 |
| 平板页面内 fetch 5 个关键 bundle | ✅ 全部 200，boot 图完整（88 模块）、模块系统 `live` |
| 页面错误采集 | ✅ 零异常（只有无害的 ResizeObserver 提示） |
| 停用第三方插件 archive-manager | ❌ 依旧不可用（排除插件冲突） |
| **换浏览器对照** | 桌面 Firefox ✅、手机 Chrome ✅、**平板华为浏览器 ❌** |

**结论**：同一条 URL、同一套模块、零异常，仅华为自带浏览器失败——**ArkWeb 内核对 Harness 客户端所用 Web 特性的支持不完整**，属于该 WebView 内核的兼容性缺陷，插件侧无法修复。

**处置**：在华为设备上使用 Chrome / Edge 等自带完整内核的浏览器访问入口即可。本插件的诊断设施保留（`~/.dsh/remote-control/sockets.log`，400 行上限）：入口 socket 生命周期 + 页面错误回传，供日后排查。

## 冻结说明

2.0.0 表示**功能面稳定**，不是"不再改动"。以下情况才值得动它：

1. 真机使用中发现具体缺陷；
2. 上游公开 API 变更导致挂载或代理失效；
3. 明确的新需求（例如入口地址二维码、TLS 字段、多地址监听）。

自动化测试（56 条）是回归基线：`node --test tests/*.test.mjs`。
